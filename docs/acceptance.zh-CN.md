# 当前验收状态

## 自动化与现场验证范围（Windows 2.0.5 / Android 2.0.4）

- TypeScript 协议、服务端和桌面构建通过，Node 5 个测试文件、15 个测试通过。
- Android 单元测试、Debug 构建、lintDebug、Release 构建与 APK v2 签名验证通过。
- 实际运行回合在独立 app-server 返回 notLoaded 时，由本机 task_started 事件识别为 inProgress；Monitor → 隔离服务 → WebSocket 验证 active/fresh。回归覆盖完成、中止、失败、部分写入、文件截断和路径变化。
- Windows 2.0.5 实测同时覆盖运行中与长期未写入的历史回合：前者保持 active/fresh，后者变为 idle/stale、错误代码 ACTIVE_EVIDENCE_EXPIRED；隔离服务端查询和 WebSocket 收到一致的修正结果。集成回归覆盖元数据不变时的证据过期、恢复写入、读取失败后过期及最终完成，上传序号连续。文档不保留现场任务 ID、任务名或个人使用记录。
- 新增回归覆盖冷启动遗留标记、5 分钟过期边界、持续写入的长任务、异常文件时间、官方等待状态与 Goal 约束；来源时间不因证据过期改成扫描时间。该窗口是有限活动推断，不等于完成了进程存活验证。
- Android 更新请求离开调用线程、时间显示与通知文案有单元回归；当前 2.0.4 的真机后台与完整 UI 验收仍未完成，不能由构建通过代替。
- 通知测试覆盖前后状态、九类中文状态标签、十秒内最终状态静默更新。
- Android 实际序列化器发送 auth/subscribe 必填默认字段，Trace 可选 null 字段省略。
- 服务端 Trace 十万条保留窗口、幂等和重启清理回归通过。
- 服务端 v2 与 Nginx 已部署，health 返回 200；Windows 2.0.5 安装包已上传并原子更新清单，包内版本和修复代码已核对，公网完整下载 87,086,600 字节的 SHA-256 与本地及清单一致。Android 保持 2.0.4，未重新构建；其既有服务器包与本地哈希一致。
- 时间回归覆盖 UTC/中国时区、跨日、纽约夏令时/冬令时及带偏移量的输入；状态变化时间不会被后续元数据时间覆盖。
- 文档检查覆盖 10 份 Markdown 的本地文件链接、客户端版本和下载链接、协议版本、SQLite schema。PowerShell 清理脚本提供固定目录清单和 -WhatIf 预览；服务端回归与性能脚本退出时清理自己创建的临时数据库。

## 未完成或有限制的验收

- Windows 当前安装包未进行 Authenticode 签名。
- Android 国产 ROM、锁屏保活、物理设备通知声音和电池策略仍需真实设备验证。
- 30 分钟 RSS/CPU 稳定性、1,000 任务端到端负载和全部 Goal/等待状态链路尚未完成，不能由短测试推断达标。
- 独立 app-server 不能直接观测 Codex 桌面的审批等待标志；没有终止事件的异常退出不能通过生命周期记录证明完成。
- 桌面/Android 全量 OpenTelemetry SDK 接入、trace 树排序及桌面日志轮转尚未完成，当前实现边界见 [Trace 文档](trace.zh-CN.md)。
- outbox 损坏后重建的序号冲突、慢订阅者跳过广播、超出 500 条的中间历史、快速重连竞态和 Android 15 前台服务超时需补充实现与验收，不能宣称已全面保证不丢事件。
- 桌面 connected 不保证上传队列为空，Windows 更新检查尚未做语义版本比较，部署脚本自动回滚也未覆盖所有配置文件；具体行为以运维、发布文档为准。

安装包、临时日志、截图和 schema 诊断导出不提交仓库。仓库中的验收结论只描述实测结果，保留上述限制，不标注为全面完成。
