# 性能与稳定性

## 目标与资源预算

服务端隔离基准 ingest p95≤50ms，任务查询 p95≤100ms；30分钟预热后RSS末次较起始增长≤50MiB。Android可控网络前台恢复目标≤5秒、进程唯一连接。桌面100线程空闲轮询p95≤300ms、活跃p95≤2s仍是目标，尚无100/1000真实线程全负载验收，不能写成已达标。

|位置|边界|
|---|---|
|桌面轮询|2秒间隔、不重入；8线程并发，每线程4详情RPC，理论32 RPC，单请求15秒|
|生命周期读取|每线程每轮2MiB，残行1MiB，之后增量读取|
|outbox|5000事件；变化批量持久化后发送；每轮最多100条/约1秒预算，单HTTP10秒；退避上限60秒|
|服务入口|HTTP/WS入站128KiB；认证订阅15秒；实时缓冲256KiB；回放500条后完整快照|
|控制/交互|控制请求256条/30秒，待答及终态各1000；初始交互逐帧等待写完|
|Trace|OTel队列2048、批256；桌面日志队列256、双文件各约5MiB；Android队列和父索引各100|
|Android UI|有序任务单项移动；回执累积1000、详情单页缓存20；Compose LazyColumn|

## 已实施优化

SQLite复用固定prepared statements，同一快照仅序列化一次。诊断不重复同步写入，OTel批量用一事务；失败不改变已提交业务结果。桌面outbox批量持久化、上传有预算，Trace上传不占用轮询等待。线程详情缓存与生命周期投影分离，保留准确的过期判断。

桌面未变化任务不重建DOM，只更新状态/时间区域；Intl.DateTimeFormat复用，Markdown交给成熟解析器。Android回执积累防止StateFlow合并丢失结果，任务更新二分定位，避免每次全列表排序；设置复用HTTP客户端，通知仅在显示内容变化时刷新。

Android通知变化保留最多1000任务的最新revision，系统发送按300ms间隔串行，最新内容替换同任务待发内容，提交后释放记录；活动任务通知保留最近40项，任务数据不清除。通知处理使用有10秒超时的短时CPU锁，空闲释放；WebSocket库心跳15秒，用更快的失效检测换取额外网络唤醒。未授予电池豁免或系统强杀时不保证息屏实时性，通知延迟与手机耗电需要分别评估。

## 本机实测口径

Node v24.15.0 / Windows x64。`npm run perf:server`在独立临时SQLite使用Fastify inject，包含同进程请求生成和响应对象；不是公网请求，也不是独立服务稳态RSS。

|场景|本轮结果|
|---|---|
|1000事件更新同一任务|总1570.02ms，p50 1.40ms，p95 2.30ms，查询1.28ms|
|另1000个不同任务，并发20|入库p95 29.85ms|
|1001任务快照查询100次|查询p95 7.34ms|
|整个测量进程|CPU 3594ms，单核平均81.83%，RSS358412288字节，事件循环p95 37.09ms|

初始同机原脚本1000事件总2229ms、p95 3ms；优化中一次同负载总1030ms、p95 2ms；最终扩展脚本的单任务阶段如上。存在运行抖动与并行构建负载，不能只挑最好样本声称固定倍数提升。多任务阶段RSS含inject客户端与100次大响应分配，不代表部署unit需要358MB。

Electron实际renderer千条合成任务约百毫秒渲染；无变化更新验证输入节点、卡片节点和焦点不变，430×600无页面横向溢出。具体本轮数字见原始报告，单次渲染不是所有机器的性能保证。

## 持续同步

30分钟真实HTTP/WS、1000任务、4477事件、5次定时重连，最终cursor与任务数匹配；持续1800.532秒，预热后RSS范围72.11–114.52MiB，末次较预热起点减少35.06MiB，末次累计单核CPU0.96%。期间最慢一分钟ingest p95 67.13ms，存在同时构建/模拟器负载。内存下降可能含GC和操作系统工作集调整，不作为永久降低内存的承诺。

该进程在server/stream模块拆分之前启动，已包含核心SQLite/Trace优化；模块拆分及初始交互背压由随后单元/界面回归验证，未再对最后一个源码状态重复30分钟。持续脚本验证任务数和cursor，不逐字段比对全部任务，也不覆盖真实Codex、手机或生产资源限制。

## 复现与观测

`npm run perf:server`断言p95门槛及快照游标/数量；`npm run test:endurance`运行30分钟并输出artifacts/acceptance/server-endurance.json。性能原始JSON可重建，不写入Git。health提供RSS、累计CPU、订阅数、数据库计数、导出失败数；CPU占用应从相邻累计采样计算。

业务事件/任务不自动删，数据库磁盘随时间增长；Trace保留不会自动VACUUM。生产长期容量、慢磁盘、真实大线程与OEM后台属于后续环境验收范围，详见[验收记录](acceptance.zh-CN.md)。
