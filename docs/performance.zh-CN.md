# 性能与稳定性

## 预算与测试口径

服务端隔离基准：单任务及20并发 ingest p95≤50ms，1001任务查询 p95≤100ms，GC后 RSS 增长≤128MiB，单核平均CPU≤80%，事件循环 p95≤50ms。脚本任何一项超限即失败。桌面100线程空闲轮询 p95≤300ms、活跃 p95≤2s是目标，不能将少量真实日志样本当成全负载达标。30分钟HTTP/WS耐久在1000个任务上持续写入、周期重连，预热后RSS末次较起始增长≤50MiB。

`npm run perf:server`使用本机 Fastify inject 与临时 SQLite。同一进程承担被测服务、请求生成、响应解析和显式GC，CPU/RSS/事件循环包含工具开销；不是公网SLA或生产unit资源保证。每次记录Node、OS、CPU、逻辑核数、内存、输入规模和原始结果，不选择性隐去失败样本。完整结果与当前验收结论见[验收记录](acceptance.zh-CN.md)。

## 已实现的优化与边界

|位置|实现及限制|
|---|---|
|协议校验|既有TypeBox Compile按schema对象缓存；仅Check，不清理字段、不转换类型，不降低严格校验|
|任务查询|SQLite预编译语句；一份递归冻结的快照缓存，只在新业务事务提交后失效；不缓存多版本历史|
|桌面轮询|2秒、不重入、8线程并发，每线程最多4详情RPC、15秒期限；初始化失败也进入后续重试|
|生命周期|增量读取，每线程每轮2MiB、残行1MiB，文件替换/缩短重建游标；证据按时效投影|
|outbox|5000事件、先持久化再发；每轮最多100条及约1秒预算，单请求10秒，失败退避最多60秒|
|服务连接|认证订阅15秒；入站128KiB；实时缓冲256KiB；回放500条后完整快照|
|控制/交互|控制请求256条/30秒；未派送等待工作站恢复7秒；待答及终态各1000项|
|Trace|OTel队列2048/批256；桌面队列256、两份约5MiB日志；Android队列和父索引各100|
|页面|未变任务不重建DOM；连接代次隔离回执；Android单连接、LazyColumn、有界详情缓存和回执|

新增缓存只减少重复解析，不删除任务、计划或细节。业务事件和任务不自动清理，数据库磁盘随使用增长；Trace只清理诊断缓存且不自动VACUUM。完整快照随任务数增长，当前不是分页协议。不要通过丢任务或扩大预算伪造优化结果。

## 运行观测

health提供RSS、累计CPU、订阅数、事件/任务/Trace计数以及诊断失败与清理计数。CPU需使用相邻采样的差值；RSS需看预热后的趋势。Trace的 `latencyMs` 使用单调时钟，跨设备ISO时间不能直接相减当网络延迟。

Android通知按300ms串行合并，普通进度声音十秒节流；短时CPU锁只覆盖通知处理。心跳、后台网络、系统通知、Doze和OEM策略各有成本与限制；模拟器不能代表所有手机耗电或锁屏行为。

## 复现

运行 `npm run perf:server` 及 `npm run test:endurance`。原始结果分别写入 `artifacts/acceptance/performance.json` 和 `server-endurance.json`，可以按[清理说明](../README.md#构建部署与清理)删除。候选优化前后必须使用相同输入，解释同机构建/模拟器竞争的影响；最终指标以当前原始结果为准。

## 当前候选实测

Node v24.15.0、Windows x64、16逻辑CPU；最终短测全部通过：20并发ingest p95 23.76ms，1001任务查询p95 3.69ms，CPU单核平均72.84%，GC后RSS147.51MiB（增长51.20MiB），GC前164.09MiB，事件循环p95 34.41ms。构建和模拟器并发时的失败样本未删除；稳定性结论仍需结合耐久及目标环境。

同进程交替5轮对照旧源码/候选，固定输入且最终数据库状态相同：每轮20,000次严格校验中位耗时2400.54→217.70ms、CPU1671→110ms；100次千任务列表查询498.59→8.02ms。该测量用于验证重复解析成本下降，不是HTTP请求延迟，不能换算为整端加速倍数。1000次入库中位耗时1472.51→1602.68ms，未观察到入库提速，不将其写成优化收益。

最终30分钟真实HTTP/WS耐久通过：1000任务、4481事件、5次重连、7次快照，最终游标一致；稳定区间RSS约87.52–95.37MiB，末次比起点下降3.26MiB，末次累计单核CPU约0.94%。最慢一分钟ingest p95为73.58ms，体现同机负载波动；短测门槛通过不保证所有分钟窗口都低于50ms。
